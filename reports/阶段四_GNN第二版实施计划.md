# 阶段四：GNN 第二版实施计划

## 计划状态

本计划已于 2026-07-13 冻结，第二版代码尚未开始实现。后续在新电脑上继续开发时，
应按本文阶段顺序推进，不直接跳到复杂模型训练，也不修改第一版测试集结果。

第二版的正式名称暂定为：

> **面向精确区域压缩收益的预算感知区域价值 GNN**

第一版输出节点种子分数，再用固定大小 BFS 扩成区域。第二版改为直接输入候选连通
区域，预测该区域对未来查询的真实净收益，并在实际索引字节预算下选择区域集合。

## 第一版结论对第二版的约束

核心 72 组验证集消融已经完成，全部 72 组成功，所有查询正确率均为 100%。关键结果
如下：

| 方法 | 平均耗时变化 | 展开节点变化 | 回退率 | Shortcut |
| --- | ---: | ---: | ---: | ---: |
| 完整第一版 GNN，5 种子 | -14.35% ± 0.62% | -21.04% ± 0.62% | 41.26% | 38,779 |
| 随机区域，5 种子 | -9.78% ± 1.37% | -15.50% ± 1.42% | 54.00% | 38,639 |
| MLP，5 种子 | -13.93% ± 0.75% | -20.14% | 34.87% | 39,071 |
| Proxy-only | -14.05% | -20.36% | 47.54% | 35,589 |
| Risk-only | -7.86% | -9.91% | 3.20% | 29,698 |
| 不使用端点风险的 GNN | -1.68% ± 0.29% | -5.51% ± 0.56% | 79.94% | 38,916 |

由此冻结以下设计判断：

1. 历史 OD 确实能够指导区域选择，完整方法稳定优于朴素随机区域。
2. 第一版主要收益来自区域端点风险处理，GraphSAGE 相对 MLP 的独立贡献尚未成立。
3. Proxy-only 已经非常强，第二版不能继续让 GNN 只拟合同一个解析代理目标。
4. 当前“内部端点整图回退”使模型被迫学习避开端点，必须先改查询系统。
5. 第二版必须输出完整候选区域价值，并使用严格的实际存储预算。

## 第二版总目标

第二版完整流程如下：

```text
全年历史 OD 时间窗口
        ↓
有向道路图节点编码
        ↓
多尺度候选连通区域
        ↓
区域池化与显式成本特征
        ↓
预测压缩收益、端点接入成本和不确定性
        ↓
实际索引字节预算下的区域集合选择
        ↓
精确 shortcut 物化与零整图回退查询
```

模型不预测路径或距离，不使用历史最短路径节点、边或边经过次数作为监督。真实查询
反馈只使用展开节点数、松弛边数和查询开销等汇总指标。

## 阶段 A：全年 Porto 数据

### 目标

当前 98,082 条可用 OD 来自前 10 万条有效轨迹，只覆盖约 21 天。原始 Porto 压缩包
实际包含 1,674,152 条有效 OD，覆盖完整一年。第二版首先建立全年数据线。

### 实现任务

1. 将 OD 抽取脚本从“读取前 N 条”升级为可处理全部有效轨迹。
2. 使用固定 Porto 城市边界，而不是根据当前 OD 样本动态确定路网裁剪范围。
3. 流式吸附 OD，避免一次性把全年轨迹全部放入内存。
4. 保留 `trip_id`、时间戳、吸附距离和吸附是否可用字段。
5. 为处理结果记录输入文件 SHA-256、路网版本和处理参数。
6. 按时间生成训练、验证和最终测试清单，不复制大 CSV。

### 时间划分

- 开发阶段使用多个滚动窗口：连续 90 天训练、随后 14 天验证、再随后 14 天测试。
- 至少选择 5 个不同季节的窗口检查时间稳定性。
- 全年最后两个月保留为最终冻结测试期，模型和参数冻结前不得读取其性能结果。
- 节点特征只能使用对应训练窗口内的历史 OD。

### 计划文件

```text
src/workload_windows.py

data/processed/porto_full/波尔图全年可用起终点查询.csv
```

大体积全年 CSV 保持 Git 忽略，只提交处理清单、统计摘要和生成脚本。

### 验收标准

- 有效 OD 数量与原始数据扫描结果一致。
- 时间跨度约为一年，时间戳单调切分无交叉。
- 吸附质量报告完整，训练、验证和测试查询 ID 不重叠。
- 同一固定输入和参数重复处理可得到相同统计结果。

## 阶段 B：精确端点局部接入

### 当前问题

压缩图删除区域内部节点。第一版只要查询起点或终点是内部节点，就整条查询退回原图。
第二版改为只在端点所属的小区域中计算临时接入距离，再继续查询压缩图。

### 查询流程

1. 起点在内部时，在其区域子图中计算起点到全部可达边界的精确距离。
2. 终点在内部时，在反向区域子图中计算全部可达边界到终点的精确距离。
3. 将这些距离作为本次查询的临时接入边，不写入全局压缩图。
4. 起终点位于同一区域时，同时计算区域内部直达距离。
5. 比较内部直达和经过压缩图的路线，返回较小值。
6. 高频端点接入向量使用有限容量 LRU 缓存，冷门端点动态计算。

### 正确性要求

任何离开压缩区域的原图路径都必须经过真实边界节点。端点到边界、边界 shortcut 和
边界到端点均对应原图中的精确真实路径，因此临时混合图既不会生成假短路，也不会遗漏
原图路径。

### 计划修改

```text
src/compression_index.py    # 增加节点到区域映射和区域局部图信息
src/indexed_query.py        # 增加临时端点接入查询
tests/test_materialized_compression.py
scripts/verify_materialized_queries.py
```

### 验收标准

- 小图穷举和 Porto 随机查询正确率均为 100%。
- 不再存在因为端点为内部节点而切换到完整原图的查询。
- 单独报告局部接入展开节点、压缩图展开节点和缓存命中率。
- 关闭缓存时结果完全一致，缓存只影响性能、不影响距离。

## 阶段 C：多尺度候选区域

### 候选设计

第二版暂不让 GNN 自由生成任意节点集合，而是建立稳定、可解释的候选池：

- 区域大小：128、256、512、1024。
- 种子来源：空间均匀锚点、图划分中心和训练期需求候选点。
- 所有候选必须连通。
- 节点集合 Jaccard 相似度过高的候选只保留成本更低者。
- 候选区域可以互相重叠，最终被选区域仍禁止重叠。

### 区域结构特征

- 节点数、内部节点数、边界节点数和边界比例。
- 进出区域的切割边数量。
- 入边、出边方向不平衡。
- 道路等级分布、平均边长和区域空间跨度。
- 实际可达 shortcut 数和序列化字节估计。

### 区域需求特征

- 区域内部起点、终点质量及其时间波动。
- 最近 1、7、30 天的起点和终点频率。
- 小时、星期周期以及需求增长趋势。
- OD 几何走廊接近或穿越区域的强度。
- 预计端点局部接入次数和接入工作量。

### 计划文件

```text
src/region_candidates.py
scripts/build_region_candidates.py
results/gnn_v2/candidate_manifest.json
```

### 验收标准

- 每个候选连通，边界定义与索引构建程序一致。
- 候选去重前后数量和阈值可追溯。
- 每种尺度都有足够候选，候选覆盖不集中在单一热点。
- 候选成本能够与真实构建后的 shortcut 数和字节数核对。

## 阶段 D：真实区域收益标签

### 标签定义

不再用几何中点 Proxy 直接作为训练目标。对候选区域 `R`，在训练期查询样本上计算：

```text
区域收益 = 原图查询工作量 - 只加入该区域后的查询工作量
```

主标签使用稳定的算法工作量：

```text
C_query = expanded_nodes + λ_relax × relaxed_edges
```

另外记录平均耗时、P95、局部接入工作量和索引构建成本，但毫秒耗时不直接作为唯一
训练目标。

### 标签生成策略

1. 先从候选池中分层选择约 1,000～1,500 个代表区域。
2. 使用固定的训练查询样本评测每个候选，保证不同候选比较口径一致。
3. 第一轮模型训练后，再选择高预测价值或高不确定候选补充标签。
4. 所有标签只来自训练期；验证期只用于选择配置，最终测试期不生成训练标签。

### 计划文件

```text
scripts/build_region_training_set.py
results/gnn_v2/region_training_labels.csv
results/gnn_v2/label_manifest.json
```

### 先验上界检查

训练 GNN 前，先使用真实训练标签运行 Oracle 选择器。如果 Oracle 与 Proxy-only 几乎
没有差距，说明当前候选池缺少可学习空间，应先改候选区域而不是增加模型复杂度。

## 阶段 E：区域价值模型

### 节点编码器

采用有向 Edge-GraphSAGE，而不是第一版无向 Mean GraphSAGE：

- 入边和出边分别聚合。
- 边特征包含长度、道路等级和单向属性。
- 默认 2 层，隐藏维度 128。
- 使用残差连接、LayerNorm、ReLU 和 0.1 Dropout。
- 完整图编码在 GPU 上一次完成，区域训练按候选小批次进行。

节点输入包括道路结构、原始起终点需求、多时间窗口需求和周期特征。手工需求扩散不再
作为完整模型必选输入，避免提前替代 GNN 的图传播作用。

### 区域表示

对候选区域内节点嵌入进行 mean、max 和 attention pooling，再拼接显式结构、需求和
成本特征：

```text
region_embedding = node_pooling + structural_features
                   + demand_features + exact_cost_features
```

### 输出头

- `benefit_head`：预测减少的全局查询工作量。
- `access_head`：预测内部端点局部接入工作量。
- `tail_head`：预测慢查询风险。
- `uncertainty_head`：预测模型不确定性。

区域净价值为预测收益减去端点接入、尾部风险和不确定性惩罚。实际存储成本直接从候选
索引统计读取，不让模型猜测可精确计算的成本。

### 损失函数

```text
L = L_huber + λ_rank × L_pairwise_ranking
    + λ_access × L_access + λ_uncertainty × L_uncertainty
```

区域选择更依赖正确排序，因此必须同时报告回归误差、Spearman 相关系数和 NDCG，不能
只报告训练损失。

### 计划文件

```text
src/gnn_region_data.py
src/gnn_region_model.py
scripts/train_gnn_region_model.py
scripts/evaluate_gnn_region_model.py
results/gnn_v2/
```

## 阶段 F：实际字节预算选择

第一版按区域数近似匹配 shortcut。第二版统一使用真实索引字节预算，目标为：

```text
最大化：预测净收益 - 区域间冗余惩罚
约束：总索引字节不超过预算，最终区域不重叠
```

先按边际净收益/字节进行惰性贪心，再执行一换一和二换一局部搜索。区域间冗余根据节点
重叠、空间邻近和需求覆盖重叠计算，避免高分区域集中在同一小片区域。

必须同时报告：

- shortcut 实际条数和序列化字节数；
- 压缩图节点数和边数；
- 区域元数据和端点缓存预算；
- 模型文件大小；
- 索引构建、模型推理和集合选择时间。

## 对比方法与核心消融

所有区域选择方法必须使用同一候选池、同一查询划分、同一精确查询程序和同一字节预算。

### 主对比

1. 随机区域。
2. 随机候选 + 相同端点成本约束。
3. Risk-only。
4. Proxy-only。
5. 解析价值/成本贪心。
6. 区域 MLP。
7. 第一版节点 GraphSAGE。
8. 第二版区域 GNN。
9. 训练期真实收益 Oracle，只作为上界。

### 精简消融

不再默认运行上百组组合实验。核心消融控制为：

- GNN 替换为区域 MLP。
- 删除时间特征。
- 删除方向和边特征。
- 删除 OD 走廊特征。
- 删除端点接入成本头。
- 删除不确定性惩罚。
- 删除区域冗余约束。
- 固定 512 节点区域替代多尺度候选。

完整模型和学习消融均运行 5 个随机种子；确定性规则运行一次。超参数只在验证集选择。

## 统一评价指标

- 平均、P50、P95 在线耗时。
- 平均展开节点和松弛边数。
- 局部端点接入展开量及缓存命中率。
- 查询加速比例。
- 索引总字节数、shortcut 数和压缩图规模。
- 索引构建、标签生成、训练、推理和区域选择时间。
- 多随机种子的均值、样本标准差和最差值。
- 查询级配对置信区间。
- 全部可达与不可达查询的正确率，必须为 100%。

实际耗时评测需要固定工作线程、预热和执行顺序；结构结论同时参考展开节点与松弛边数，
避免服务器瞬时负载改变结论。
