# 阶段四：第一版 GNN 大型消融实验报告

## 当前状态

**实验脚本已经准备，正式实验尚未运行。** 本报告当前记录冻结后的实验设计、控制变量、
运行方式和完成标准。服务器实验结束后，应直接依据聚合 CSV 填写结果，不得把计划值写
成实测值。

## 实验目的

第一轮结果证明“GraphSAGE 节点打分 + 区域端点风险修正”整体优于随机均值，但不能
区分收益来自图消息传递、需求特征、代理目标还是区域选择器。本轮实验通过严格控制变量
回答以下问题：

1. 图消息传递是否优于参数规模相近的 MLP？
2. 原始端点频率和扩散需求特征分别贡献多少？
3. 几何中点目标是否优于起终点需求重叠目标？
4. 节点级端点惩罚和区域级端点风险惩罚是否必要？
5. 需求扩散步数和区域风险系数是否稳定？
6. 第一版结论在 5 个模型随机种子下是否成立？

## 固定条件

- 数据：Porto 98,082 条有效 OD，按时间 70%/15%/15% 划分。
- 测试集：14,713 条，只用于最终精确配对评测。
- 模型训练：CUDA GPU，最多 200 轮，早停耐心 30 轮。
- 区域大小：512。
- GNN 区域数：85。
- 候选种子上限：80,000。
- 完整模型扩散步数：3。
- 完整模型扩散重启系数：0.4。
- 完整模型节点端点惩罚：2。
- 完整模型区域端点风险惩罚：200。
- 模型随机种子：1、2、3、4、5。
- 正确性：每组测试期查询必须保持 100%。

除当前行明确列出的变量外，其余训练、选区、索引构建和评测参数保持不变。

## 消融矩阵

| 类别 | 变体 | 相对完整模型唯一变化 |
| --- | --- | --- |
| 完整模型 | `full` | 无 |
| 非学习基线 | `risk_only` | 不训练模型，仅按低节点端点风险和区域端点风险选区 |
| 非学习基线 | `proxy_only` | 不训练模型，直接使用解析代理目标和区域端点风险选区 |
| 纯 GNN | `gnn_only_no_endpoint_risk` | 同时删除节点目标端点惩罚和区域端点风险惩罚 |
| 模型结构 | `mlp_no_message_passing` | GraphSAGE 替换为同深度 MLP |
| 输入特征 | `no_diffused_demand_features` | 删除扩散后的起点、终点需求 |
| 输入特征 | `no_raw_endpoint_frequency` | 删除原始起点、终点频率 |
| 道路特征 | `no_coordinates/no_degree_features/no_mean_edge_length` | 分别删除坐标、度和平均出边长度 |
| 节点风险 | `no_endpoint_proxy_penalty`、`endpoint_penalty_*` | 节点端点惩罚比较 0、0.5、1、2、4、8 |
| 代理目标 | `demand_overlap_target` | 几何中点目标替换为扩散起终点场重叠目标 |
| 扩散步数 | `diffusion_steps_*` | 比较 0、1、3、5、8、12、20 步 |
| 扩散重启 | `diffusion_restart_*` | 比较 0、0.2、0.4、0.6、0.8 |
| 扩散交互 | `diffusion_steps_*_restart_*` | 对 5、8、12、20 步分别比较 0.2 和 0.6 重启 |
| 区域选择 | `region_risk_penalty_*` | 区域风险惩罚比较 0、50、100、200、400、800 |
| 候选规模 | `candidate_limit_*` | 候选池比较 20,000、40,000、80,000、120,000 |

核心套件包含 14 个学习变体，每个运行 5 种子，并加入 2 个确定性非学习基线，共
**72 组实验**；完整套件包含 40 个学习变体和 2 个确定性基线，共 **202 组实验**。
默认只运行核心套件，完整套件作为可选补充。随机区域 5 种子和 OD 热点基线只运行
一次并保存在公共参考目录，避免每个消融组重复计算。完整套件不是全组合网格，而是以严格
单变量实验为主，并增加 8 个最关键的“扩散步数 × 重启系数”交互组，控制总成本。

## 运行与恢复

统一入口为 [`scripts/run_gnn_ablation.py`](../scripts/run_gnn_ablation.py)。脚本具备以下
行为：

- 每组使用独立目录和 `run.log`。
- 训练完成立即保存模型、节点分数和训练摘要。
- 评测完成立即重建聚合表 `ablation_runs.csv`。
- 再次运行时跳过已经完成的训练或评测阶段。
- 单组失败写入 `failed_runs.txt`，其他组继续运行，最终返回非零状态。
- `--restart` 才会删除整个消融输出并从头运行。
- `--dry-run` 默认只打印 72 组核心计划，不读取数据、不训练。
- `--suite comprehensive` 才运行 202 组扩展实验，并复用已有核心结果。
- 大型消融默认评测验证集；只有冻结最终配置后才允许使用 `--evaluation-split test`。

服务器后台命令和日志查看方式见项目根目录 README。正式实验启动前先执行干运行检查，
不要手工逐组修改命令。

## 结果文件

正式运行后应生成：

```text
results/gnn_ablation/
├── ablation_manifest.json
├── ablation_runs.csv
├── failed_runs.txt                 # 全部成功时不存在
├── runner.log
├── reference/
│   ├── evaluation_summary.csv
│   └── run.log
└── runs/
    └── <variant>__seed<seed>/
        ├── model.pt
        ├── node_scores.csv
        ├── training_summary.json
        ├── evaluation_summary.csv
        └── run.log
```

`risk_only` 和 `proxy_only` 目录不带随机种子后缀，并使用 `scoring_summary.json` 代替
`training_summary.json`。

`ablation_runs.csv` 是后续统计分析的唯一主表；单组目录用于核查训练过程、节点分数和
失败原因。

## 主要指标

每个学习变体应汇总 5 个随机种子的均值、样本标准差和最好/最差值；两个确定性基线
各运行一次：

- 验证代理目标 Pearson 相关系数。
- shortcut 数、内部节点数和压缩图规模。
- 验证查询回退率。
- 平均耗时变化和 P95 耗时变化。
- 平均展开节点变化。
- 查询加速比例。
- 预处理时间、评测墙钟时间、GPU 训练时间和峰值显存。
- 精确查询正确率。

耗时容易受服务器负载影响，核心结构结论应同时参考展开节点数、回退率和查询加速比例，
不能只按单次毫秒数排序。

## 完成标准

只有同时满足以下条件，才能把本报告状态改为“已完成”：

1. 核心 `ablation_runs.csv` 包含 72 个不重复运行组。
2. 14 个核心学习变体各自包含随机种子 1～5，两个确定性基线各包含一组。
3. 所有组正确率均为 100%。
4. `failed_runs.txt` 不存在。
5. 公共随机与热点基线完成。
6. 报告补充均值、标准差、控制变量比较、负结果和最终结论。
