## 2. 正式标签当前数字

对 1,200 个候选、每个 2,000 条固定后续查询：

- 候选全部完成；
- 距离正确率下界 100%；
- 平均收益均值 39.695；
- 平均收益标准差 40.853；
- Oracle Top-120 平均收益 134.908；
- 第一版 Proxy Top-120 平均收益 133.161；
- Oracle 相对 Proxy 差 1.747；
- 原始频率 Top-120 平均收益 126.037。

这些数字证明“标签具有差异”和“Proxy 仍有剩余空间”，不证明 GNN 已经学到这部分空间。

## 7. 当前脚本怎样运行

以下命令都假设已准备 Porto 数据和 Python 环境。

### 重新生成候选池

```bash
python scripts/build_region_candidates.py
```

当前候选已固定，除非明确要开启新实验版本，否则不应随意重跑并覆盖清单。

### 生成正式标签

```bash
python scripts/build_region_training_set.py \
  --query-sample 2000 \
  --query-sample-seed 42 \
  --workers 16
```

当前任务已经完成。相同身份重跑会读取清单并发现没有待处理候选。

### 分析正式标签

```bash
python scripts/analyze_region_labels.py
```

默认会校验正式标签清单，并写 `results/gnn_v2/label_analysis.json` 和 `label_analysis.md`。
当前结果类型为 `formal_sampled_labels`，阶段状态为 `ready_for_modeling`。

### 分析两批标签稳定性

```bash
python scripts/analyze_region_labels.py \
  --labels 第一批.csv \
  --comparison-labels 第二批.csv \
  --json-output 分析.json \
  --report-output 分析.md
```

### 构建统一数据并训练 MLP

```bash
.venv-gnn/bin/python scripts/build_demand_field_dataset.py
.venv-gnn/bin/python scripts/train_demand_field_model.py
.venv-gnn/bin/python scripts/evaluate_demand_field_model.py
```

### 训练基础 NBFNet

正式五种子训练只在 CUDA GPU 上运行。实际完成的首轮配置是 32 维隐藏状态、6 层传播、
每块 8 个需求原型、100 个最大 epoch 和 20 个早停耐心值。训练先计算全 128 原型混合预测，
再逐块重算并累积精确梯度，因此块大小只控制显存，不改变训练目标：

```bash
PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True \
.venv-gnn/bin/python scripts/train_demand_field_nbfnet.py \
  --seeds 42,43,44,45,46 \
  --hidden-dim 32 \
  --layers 6 \
  --prototype-batch-size 8 \
  --max-epochs 100 \
  --patience 20
```

结果写入 `results/gnn_v2/nbfnet_base/`。名称含 `nbfnet_smoke` 的目录只记录本机链路验证，
被 Git 忽略，不能作为正式结果引用。

RTX 3050 4GB 已用同样的 32 维、6 层、128 原型结构跑通 1 epoch：78.42 秒，峰值已分配
显存 1.17 GiB。这个数字证明执行与显存链路成立，不属于正式模型效果。

当前统一数据摘要为 `e9b1bc149a6a94dd744305e41817c3a2b9447cd5e3ba5a17c71fea38db2bf261`。
重新构建数据后摘要会变化，旧模型会因摘要不匹配而拒绝评测。

## 8. 当前最合理的下一步顺序

### 第一步：完成基础 NBFNet 正式五种子训练

该步骤已经完成。五种子整体 Spearman 与 MLP 基本持平，但 NDCG@K 和 Top-K 收益超过
MLP 与原始频率，因此允许进入核心消融，不足以单独证明道路拓扑贡献。

### 第二步：运行严格纯传播四组实验

该步骤正在执行。四组统一使用空间隔离 split、32 层、相同隐藏维度与训练预算；最终读出
不含第 0 层，预测头不读取 64 维区域特征，并额外报告参数量、显存、运行时间、固定
K=5/10/18 指标和候选节点冗余。

### 第三步：按结果决定是否扩数据

若纯传播出现明确且可重复的信号，再扩展独立候选、时间窗口、尺度和城市；若仍失败，则
接受传播在当前任务上没有必要或无法被当前监督识别，不继续堆叠结构。

### 第四步：固定预算选区并做未来配对评测

处理候选重叠与 shortcut 预算，构建多区域索引，在隔离的未来窗口中逐查询比较原图与压缩
查询，并保证正确率 100%。

### 第五步：所有配置冻结后运行最终测试

最终测试只运行一次，不能反复查看后调整模型，否则它会变成验证集。

## 9. 哪些事情现在不应抢先做

按照冻结计划，以下内容应等核心传播闭环成立后：

- Porto 全年 167 万 OD；
- 128、256、512、1024 多尺度候选；
- 自由区域生成；
- 复杂集合局部搜索；
- 不确定性预测头；
- 第二城市迁移；
- 在线增量训练；
- Shapley 集合贡献估计。

先扩展这些变量会让传播失败时难以定位原因。

## 10. 第二版最终完成标准

第二版只有同时满足以下条件才算完成：

1. 内部端点不整图回退，查询正确率 100%；
2. 真实标签不含路径监督，且时间窗口无泄漏；
3. 损失能更新起点场、终点场、注意力、门控和深度融合；
4. 双向可学习传播稳定优于原始频率、固定扩散和 MLP；
5. 删除任一方向或道路方向都会可复现地变差；
6. 所有主方法使用相同候选、时间划分和预算；
7. 同时报告排序、工作量、毫秒耗时、索引成本、正确性和多种子波动；
8. 在查看最终测试结果前冻结模型与超参数。

当前已经完成第 1 条和第 2 条的数据基础，但第 3 至第 8 条仍待模型与最终实验验证。
