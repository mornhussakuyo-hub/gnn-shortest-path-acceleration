## 这套文档回答什么

这套文档假设读者第一次接触图、最短路、压缩索引、机器学习和 GNN。目标不是只告诉你

1. 这个项目究竟想解决什么现实问题；
2. 道路为什么可以表示成“图”；
3. 最短路查询为什么会慢；
4. 区域压缩为什么可能让查询变快，同时仍保持答案精确；
5. 第一版 GNN 做了什么，又为什么不足以证明 GNN 的作用；
6. 第二版为什么最终确定为“OD 条件化双向 NBFNet”；
7. 第二版从提出、纠偏、实现端点接入，到候选池和真实收益标签完成的全过程；
8. 项目中的 Oracle 到底是什么，为什么它只能当上界，不能当作可部署方法；
9. 截至当前，哪些代码已经存在，哪些仍然只是实施计划；
10. 为什么已经先完成 MLP，以及如何运行 NBFNet 正式训练。

## 最重要的一句话

第二版**不是让神经网络计算最短路径**，也不是把 NBFNet 当作在线路由器。它想让神经网络只做一件事：

> 根据过去一段时间的起点、终点需求和有向道路结构，预测哪些固定道路区域在未来最值得
> 被压缩；区域选定后，仍由精确算法构建索引并回答最短路查询。

因此，机器学习负责“选哪里”，经典算法负责“怎么算”，最终距离必须与原图精确最短路
完全一致。

## 如果你只想先知道 Oracle

可以直接阅读 [08：Oracle 到底是什么](08_Oracle到底是什么.md)。最简短的答案是：

> Oracle 是一个“已经偷看了真实收益标签，再按真实收益从高到低排序”的理想选择器。

它不是 Oracle 数据库，不是某个 GNN，也不是项目要部署的算法。它代表：在当前候选池和
标签定义不变时，理论上能选出的最好候选集合，用来衡量 Proxy 或学习模型距离“已知答案
后的最优排序”还有多少空间。

## 当前状态的极简结论

截至 2026-08-01：

- Porto 道路图、98,082 条 OD、精确基线、传统区域压缩和预算扫描已经完成；
- 第一版 GNN 已归档，其主要收益被证明更多来自端点风险和几何 Proxy，而不是
  GraphSAGE 本身；
- 第二版阶段 0 的精确端点局部接入已经完成，内部端点不再整条查询回退原图；
- 已固定 1,200 个全图随机候选区域，每个区域 512 个节点；候选生成不读取历史 OD，
  覆盖 97.58% 的道路节点；
- 正式的 `1,200 × 2,000` 单区域收益标签已经全部生成，清单状态为 `complete`；
- 所有候选的距离正确率都是 100%；
- 正式标签上 Oracle Top-120 平均收益为 134.908，第一版 Proxy 为 133.161，差值为
  1.747 个平均展开节点；
- 第二版主模型已经确定为 **OD 条件化双向 Neural Bellman-Ford Network（NBFNet）**；
  普通 MLP、固定扩散、GraphSAGE 和无向传播只保留为严格对照；
- 空间重叠组隔离、未来窗口与度保持重连消融已经在 Porto/Chicago 完成；正确道路邻接对全局
  排序的独立贡献在两城复现；
- Z0 是无参数、无标签的双向多深度传播主方法；Porto/Chicago holdout Spearman 分别为
  `0.9356 / 0.9411`；
- 32 层 G4 使用 `score=z0+residual` 与 soft Spearman。三个种子的 holdout Spearman 为
  Porto `0.9459 ± 0.0017`、Chicago `0.9468 ± 0.0011`，未来全候选为
  `0.9566 ± 0.0016 / 0.9257 ± 0.0009`，全部种子均超过各自 Z0；
- G4 改善的是全局排序，不是所有 Top-K。Chicago holdout NDCG@18 低于 Z0，Porto 在线增量
  很小，因此最终部署主方法仍是 Z0，G4 是可选神经增强；
- 两城严格非重叠、多预算、当前/未来在线闭环全部完成，所有距离正确率 100%；
- P 预训练没有启动；实验主线已经关闭，剩余工作是论文图表、写作和比赛材料。
